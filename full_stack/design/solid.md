# Introduction

[SOLID](https://en.wikipedia.org/wiki/SOLID) is a mnemonic acronym, introduced by Robert C. Martin in 2000 [1], for the following five principles:

1. [Single-Responsibility Principle (by Robert C. Martin)](https://en.wikipedia.org/wiki/Single-responsibility_principle): A class or module should have one responsibility and therefore one reason to change.
   
2. [Open–Closed Principle (by Bertrand Meyer)](https://en.wikipedia.org/wiki/Open%E2%80%93closed_principle): Software entities (classes, modules, functions, etc.) should be open for extension, but closed for modification (without modifying the source code).
   
3. [Liskov Substitution Principle (by Barbara Liskov)](https://en.wikipedia.org/wiki/Liskov_substitution_principle) by: A subclass should be usable wherever its parent class is expected without breaking the program.
   
4. [Interface Segregation Principle (by Robert C. Martin)](https://en.wikipedia.org/wiki/Interface_segregation_principle): A class should not be forced to depend on methods it does not use.
   
5. [Dependency Inversion Principle (by Robert C. Martin)](https://en.wikipedia.org/wiki/Dependency_inversion_principle):
  - Abstractions (e.g., interfaces) should not depend on concrete implementations (details).
  - High-level modules should not depend on (or import from) low-level modules. Both should depend on abstractions.
